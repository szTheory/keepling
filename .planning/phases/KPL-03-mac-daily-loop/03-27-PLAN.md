## The choice is made here, not by the executor: AMEND the spec, and build the missing size dimension

VERIFICATION.md offers two resolutions — build a desktop visual-snapshot lane, or amend the UI-SPEC
and correct the sign-off. **This plan chooses to amend, and to build behavioral evidence for the one
dimension amendment cannot cover.** The reasoning, so it can be argued with rather than accepted:

1. **A golden image here would assert the wrong thing.** This repository has no git remote, so
   `.github/workflows/` has never executed (O-35). Baselines could only ever be recorded and
   compared on one developer's Mac. Such a baseline proves "nothing changed on this machine since I
   pressed record" — not that the interface is legible or correct. `tooling/verify-macos-integration.mjs`
   documents this exact failure mode in its own source: a lucky sample became durable green.
2. **Stronger evidence for these properties already exists.** macOS rows A10 (Increase Contrast),
   A12 (Reduce Transparency), A13 (Reduce Motion) and A14 (live light/dark change) launch the
   packaged application, apply the REAL OS setting, and measure a WCAG contrast ratio over the
   window's REAL rendered pixels, failing below 4.5:1. That measures legibility. A golden image
   would only compare bytes against a stored PNG.
3. **The emulatable properties are already covered behaviorally.** `apps/desktop/test/e2e/accessibility.spec.ts`
   covers 200% reflow, colorScheme-driven theming, forced-colors, prefers-reduced-motion, and a
   theme/contrast/motion change mid-dialog.
4. **AGENTS.md sets the bar explicitly:** "Native platform conventions and usability outrank
   pixel-identical cross-platform UI." Pixel identity is not this project's quality standard.
5. **One dimension is genuinely uncovered and is therefore BUILT, not amended away:** the five named
   window sizes. Nothing in the repository resizes the desktop window and asserts the result. Task 1
   and Task 2 close that with machine-independent behavioral assertions.

## A finding that surfaced while making this decision, and is NOT silently dropped

`03-UI-SPEC.md` line 334 makes a layout claim: "The 1024-1063px case proves drawer navigation plus
360/480px list/detail minimums; 1064px proves the first 224/360/480px persistent composition."
`apps/desktop/renderer/desktop.css` contains **zero media queries** and a fixed `320px 1fr` grid,
and `git grep -i drawer -- apps/desktop` returns nothing. That responsive composition is UNBUILT.

This is an unbuilt feature, not missing evidence, so it is outside this gap's scope — but it is not
deleted and not implied to be proven. Task 3 records it as an explicit NOT PROVEN / NOT BUILT
disclosure in the spec, with the two grep results as its evidence, so a later phase decides
deliberately whether to build it. If the developer wants it built instead, that is a new phase, not
a quiet edit here.
</gap_2_decision>
