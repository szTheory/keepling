## ⚠ Read This Before Dispatching Any Executor

**1. Isolation must be re-armed to `none` before EVERY dispatch.**
This repository has **no git remote**, so `origin/HEAD` is unresolvable and
`worktree.base-check` returns `shouldDegrade: true` / `fork-ref-unknown`. GSD's sequential
fallback is correct and expected (#683) — do NOT force worktree dispatch, and do NOT create
a remote to "fix" it.

However, `dispatch-isolation` re-resolves to `harness-worktree` on every read and re-persists
that to the sentinel as a side effect. If you dispatch without re-arming, the isolation guard
hook **refuses the Agent() call**. Before each dispatch run:

```sh
node "$HOME/.claude/gsd-core/bin/gsd-tools.cjs" query dispatch-isolation --raw --phase KPL-03 --force-isolation none >/dev/null
cat .gsd/dispatch-isolation-sentinel.json   # expect {"isolation":"none","harness_flag":null,...}
```

Do NOT set `workflow.use_worktrees=false` in config to work around this — the degrade is a
property of the current repo state, not a project preference.

positional, so the command runs the **entire** desktop suite regardless of the name passed.
Several plan `<verify>` blocks use this form. The evidence is still valid (the full suite
contains the named tests) but a count from it is **not lane-scoped** — never report it as
