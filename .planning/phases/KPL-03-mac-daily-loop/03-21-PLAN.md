## Task 1 — O-36, Escape silently stops working

Measured: after dismissing the Quick Entry discard confirmation with **Keep
Draft**, AX focus lands on `AXWebArea "Keepling"` -- the document -- rather than
on a control. `apps/desktop/renderer/quick-entry.tsx:103` binds the handler as
`<div onKeyDown={handleKeyDown}>`, and React's synthetic keydown only fires for
keys delivered INTO that subtree. With focus on the document body the event
never reaches it, so Escape does nothing and gives no feedback. Tabbing back
into the field makes the very same Escape work immediately. Reproduced twice
with a standalone AXProbe.

Two independent things are wrong, and BOTH deserve fixing:

1. The confirmation does not restore focus to a control when it closes. A dialog
   that returns focus to nowhere is a keyboard-navigation defect in its own
   right, and it is what D-06/MAC-02 mean by focus restoration.
2. The window's Escape handling depends on where focus happens to be. Even with
   (1) fixed, any future focus-to-body path silently disables the key. Bind at a
   level that does not care -- the window/document -- so the guarantee is
   structural rather than incidental.

Fix both. Fixing only (1) leaves the trap armed for the next dialog.

Note `usableFocus()` in `tooling/verify-macos-integration.mjs` currently ACCEPTS
the `AXWebArea`, which is why row A6 is blind to this. Tightening it is a
legitimate follow-up but is explicitly NOT this plan's job -- it would turn
other rows red for unrelated reasons. Leave it, and record the decision.

## Task 2 — O-34, the adapter has never met a server

`apps/desktop/test/e2e/real-stack-sync.spec.ts` is named for a real stack and
does not have one. It constructs `KeeplingSyncAdapter` with a stubbed `fetch`
against `https://server.keepling.invalid`, a deliberately non-resolving host.
Every spec in `test/packaged/` sets `KEEPLING_TEST_SYNC_MODE` and exercises the
inline stub. The only desktop test touching localhost is `gap-closure.spec.ts`,
which stands up a bare 500-responding loopback server to prove offline
DETECTION. So nothing has ever verified that the adapter and the server agree.

`apps/web/e2e/support/stack.ts` ALREADY spawns real PostgreSQL and real Phoenix
for the web lane. Reuse it. Do not reimplement it, and do not copy it -- import
it or factor the shared part out, so the desktop lane cannot drift from the
harness the web lane proves against.

The new lane must:

  - launch the PACKAGED executable from the manifest, exactly as the other
    packaged specs do (they already spread `...process.env`, so pointing the app
    at a base URL is configuration, not plumbing);
  - leave `KEEPLING_TEST_SYNC_MODE` UNSET so the real adapter runs;
  - obtain credentials through the real device-grant path 03-14 wired, against
    the real server;
  - capture while the server is unreachable, then reconnect and settle;
  - assert Synced appears ONLY on a receipt matching both mutation identity and
    fingerprint, and never for a mutation the server did not acknowledge;
  - preserve the exact serialized command bytes across the retry.

If the server genuinely cannot be started in this environment, that is a LOUD
FAILURE, never a skip -- report it with the actual error and stop. Do not
silently degrade to a fake; that is the defect being removed. Note the recorded
sandbox caveat: a PostgreSQL `shmget: Operation not permitted` failure is an
execution-environment limitation rather than a product regression, and if that
is what you hit, say so explicitly and report rather than working around it.
