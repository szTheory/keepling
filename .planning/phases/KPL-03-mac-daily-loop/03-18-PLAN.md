<objective>
Remove the sleep-then-read-once pattern from every row of the macOS integration lane, so a green lane means the product works rather than that the machine happened to be fast.

Purpose: Five rows have now flaked on bytes that never changed -- A6, A4, A7, A14 and A3 -- each fixed individually while the shape that produced them stayed. Combined with digest-bound caching this is actively dangerous: one lucky run becomes durable green until the artifact changes. A14 demonstrated it, passing at 20:54:21 and failing thirty minutes later on identical bytes, with the passing sample cached and served to the gate.
Output: A lane that settles on conditions, a measured flake rate, and a gate green on evidence recorded with these fixes in place.
</objective>

<design_guidance>
Measured facts, established before this plan was written:

* Five rows have flaked on unchanged artifacts. A6 (fixed `fbdf2b4`), A4 and A7
  (fixed by the 03-17 executor), A14 (fixed `9cc7ec5`), A4 again and A3 (A4
  fixed `55b9398`; A3 is still open and is what this plan starts from).
* The shape is always the same: `postKeys(...)`, `await sleep(N)`, one
  `focusedElement(handle)` read, then a `check(...)` on it. The AX tree
  legitimately reports no focused element for a beat while a dismissed dialog's
  node unmounts and focus moves, so the single sample races that beat.
* Confirmed sites at the time of writing (line numbers will drift -- find them
  by shape, not by number): `917` and `934` in A2, `966` in A3 and the
  conflict-heading read later in A3, `1151`, and the inline reads at `1212` and
  `1231`. `tabUntil` (`799`) and `settledFocus` (`544`) already poll.
* `settledFocus` now accepts an `until` predicate (added in `55b9398`) which
  polls for the caller's condition rather than for quiescence. That is the
  idiom to spread. Do not reinvent a second one.
* Load matters and must be part of the acceptance measurement: A3 took 16.2s
  against its usual 5.5s during the run where A4 failed, and A4 took 31.3s.
  A fix that only holds on an idle machine has not fixed anything.
* The lane's evidence is now bound to this file's own digest, so ANY edit here
  invalidates prior evidence and forces a genuine re-record. Expect that.

The generalisable rule, which is worth stating in the code so the next person
does not reintroduce it: poll for the condition you are about to assert, never
for the absence of change. Both `null` focus and a pending dead key are stable
indefinitely, so a quiescence check settles happily on the failure. The 03-17
executor hit exactly this and caught it by measurement.
</design_guidance>

<task_1>
**Convert every sleep-then-read-once site to settle on its asserted condition.**

Find the sites by shape across the whole file, not only the ones listed above:
a `sleep()` followed by a single AX/appearance/focus read whose value is then
passed to `check(...)`.

Use the existing `settledFocus(handle, { until })` idiom for focus reads. For
non-focus reads (appearance repaint, node presence) use the existing `waitFor`
helper. Add no third mechanism.

Where a read is genuinely a SAMPLE rather than a condition -- a value the row
records for later comparison rather than asserts on immediately -- leave it
alone and say in the SUMMARY why it is not a race.

Verify: `node --check` passes and `--rows A2,A3` runs green.
</task_1>
