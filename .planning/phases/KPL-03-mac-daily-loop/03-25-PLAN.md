<objective>
Make the packaged Mac artifact byte-identical across separate builds at one revision, so the gate's
digest-bound macOS evidence stops dying on every rebuild.

Purpose: closes half of VERIFICATION.md Gap 1. `tooling/verify-desktop-phase.mjs` packages the app
itself (the `package-once` lane) and then asks `verify-macos-integration.mjs --gate` for evidence
bound to the digest it just produced. Because packaging is not reproducible across separate
invocations (O-40 — three digests at one clean revision), every gate run manufactures a digest that
no recorded evidence can ever match. That is why the lane is *structurally* unable to pass, not
merely unlucky. Fixing packaging fixes it at the source and leaves the digest binding fully strict.
Output: a reproducibility comparator that can prove it detects differences, a deterministic build,
verified artifact reuse, and a `package-reproducible` lane in the phase gate.
</objective>

<design_guidance>
## Why this is the load-bearing fix, and what it is NOT

The prohibition against loosening the digest binding is already recorded in 03-24-PLAN.md and still
binds. It is not an obstacle here: with reproducible packaging the binding never needs loosening,
because the digest stops moving. Read the direction of the fix carefully — the evidence design is
correct, the build is what is wrong.

There is a second, independent contributor that reproducibility alone does not remove: the gate
rebuilds on every invocation. Even a perfectly reproducible build wastes an Electron make on every
run, and any future divergence immediately re-invalidates evidence. Task 3 removes the churn by
letting `package-desktop.mjs` reuse an artifact whose `inputDigestSha256` is unchanged — but ONLY
after re-hashing the artifact on disk and proving it still matches its manifest. That is not a
loosening: nothing is trusted, the bytes are re-measured.

## What is already known about the divergence

`hashDirectory` (tooling/package-desktop.mjs) hashes relative path, octal mode, symlink target and
file content — it does NOT hash mtimes, so the difference is real bytes or a real mode, not a
timestamp on an inode. REQUIREMENTS.md's O-40 correction records the discriminating observation:
two back-to-back invocations in ONE shell agreed, three separate invocations at clean revision
fc3ac82 did not. Do not build a hypothesis on that asymmetry — measure it. The candidate surfaces
worth naming so the comparator descends into them: `Contents/Resources/app.asar` (the vite build
output, packed by @electron/asar), `Contents/_CodeSignature/CodeResources` (ad-hoc signature),
`Contents/Info.plist`, and the Mach-O executable.

## Anti-vacuousness is a hard requirement for the comparator

A comparator that reports `differing_entries=0` because it compared nothing, compared the same
directory to itself, or silently skipped an unreadable entry would be worse than no comparator. The
self-test in Task 1 is not optional decoration — it is what converts a green report from an
impression into a measurement. Follow the idiom the macOS lane already uses at
`tooling/verify-macos-integration.mjs` `SELF-TEST-EVIDENCE`: the tool proves its own rules on
synthetic input before it is trusted on real input.

## If a residual difference cannot be eliminated

Report it. Do not hide it, do not exclude the entry from hashing, and do not declare the gap closed.
If Task 2 finds a difference source that genuinely cannot be removed without changing what is
shipped, STOP and report it with the named entry and the reason — the fallback evidence-design route
is a decision for the developer, not something to improvise inside this plan.
</design_guidance>
