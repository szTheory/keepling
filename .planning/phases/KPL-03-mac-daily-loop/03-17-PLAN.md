<objective>
Cut the cost of a local test run to the signal it actually produces, without weakening the gate.

Purpose: The comprehensive suite is correct and must stay. What is wrong is that it is also the DEFAULT for someone changing one file, and that the documented way to scope it silently does not work. Measured: `pnpm test:desktop -- keyboardCommands` runs 18 files / 164 tests, while `pnpm test:desktop keyboardCommands` runs 1 file / 19 tests. The `--` is swallowed and the filter is lost, with no warning.
Output: Working filter forwarding, a change-scoped selector, an opt-in headless E2E mode, and a CI job that settles the TCC question by experiment.
</objective>

<design_guidance>
Measured facts, established before this plan was written -- trust these, verify anything else:

* Four test layers exist. `pnpm test:desktop` (vitest, 5 projects) and
  `pnpm test:desktop:ipc` are ALREADY headless -- they present no windows and
  are not the problem. `pnpm test:desktop:e2e` (8 Playwright specs under
  `apps/desktop/test/e2e/`) launches real Electron windows. The macOS lane
  presents windows and posts real OS keystrokes by design.
* Windows are constructed `show: false` and shown later by an explicit
  `.show()` (`main-window.ts:34`, `quick-entry-window.ts:212`,
  `settings-window.ts:49`). Playwright drives the renderer over CDP, which does
  not require a visible window -- that is the hook headless mode should use.
* `.github/workflows/desktop.yml` already runs on `macos-15` with a
  build-once/download-many artifact discipline: `desktop-package` builds and
  records the manifest, and every test job downloads it and NEVER rebuilds.
  A new job MUST follow that same discipline.
* `tooling/verify-macos-integration.mjs` already supports `--all`, `--rows`,
  `--gate`, and `--without-accessibility-trust` (rows needing no Accessibility
  grant). Row trust requirements are declared per row in its registry:
  `requiresAccessibilityTrust`, `requiresProtectedSettingsWrite`,
  `requiresScreenRecording`.
* Env flag convention in this repo is `KEEPLING_TEST_*` (see
  `KEEPLING_TEST_SYNC_MODE`, `KEEPLING_TEST_EXPOSE_INTERNALS`).

On the TCC experiment: it is genuinely unknown whether a GitHub-hosted
`macos-15` runner can be granted Accessibility, Screen Recording or Full Disk
Access. Do not design around either answer. Run the subset that provably needs
no Accessibility grant, have the job REPORT what the runner could and could not
do, and let one real run settle it. An honest "inconclusive, here is the
output" is a successful outcome for this task; a confident claim without a run
is a failure.
</design_guidance>

<task_2>
**Add `pnpm test:changed` -- change-scoped lane selection.**

Create `tooling/select-tests.mjs`, which diffs the working tree (and staged
changes) against `HEAD`, maps changed paths to the minimum set of lanes that
can actually observe them, prints the selection WITH its reasoning, and runs
exactly those lanes.

The mapping must be conservative: when a changed path cannot be confidently
attributed, select MORE rather than fewer lanes and say why. A selector that
silently under-selects produces false confidence, which is worse than a slow
run. Print the escape hatch (`pnpm verify:desktop-phase`, or whatever the gate
entry point is) in the output every time.

Suggested starting mapping, to be corrected against the real tree:
  * `packages/web-ui/**`                -> renderer vitest project
  * `apps/desktop/main/windows/**`      -> e2e + (if packaged bytes change) macOS lane
  * `apps/desktop/preload/**`, IPC contracts -> ipc project + e2e
  * `apps/desktop/main/store/**`, worker -> store/worker/performance projects
  * `tooling/**`, `.github/**`          -> no test lane; say so explicitly
  * anything unmatched                  -> everything, with the reason printed

Verify: show the tool's output for at least three genuinely different changed
paths, including one unmatched path that correctly widens to everything.
</task_2>

<task_3>
**Give the Electron E2E suite an opt-in headless mode.**

Under `KEEPLING_TEST_HEADLESS=1`, the app must not present visible windows;
Playwright continues to drive the renderer over CDP.

First MEASURE which of the 8 specs still pass headless. Some assert real focus,
window ordering or menu behaviour and will legitimately fail -- those are not
bugs to paper over. Tag the specs that require a visible window so they are
excluded when headless and run normally otherwise, and record in the SUMMARY
exactly which specs are headless-capable and which are not, with the failure
that disqualified each one.

Do not set headless as the default for CI. CI has no screen to take over and
benefits from the windowed path being exercised.

Verify: paste `KEEPLING_TEST_HEADLESS=1 pnpm test:desktop:e2e` output showing
the headless-capable specs passing, plus the per-spec capability table.
</task_3>

<task_4>
**Run the macOS integration lane in CI and settle the TCC question.**

Add a job to `.github/workflows/desktop.yml` that runs on `macos-15`, downloads
the packaged artifact produced by `desktop-package` (never rebuilding, matching
the existing jobs' discipline), and runs
`node tooling/verify-macos-integration.mjs --without-accessibility-trust`

Mark the job non-blocking (`continue-on-error`) for this first run ONLY,
because its purpose is to answer an open question. Record in the SUMMARY that
it is non-blocking and that a follow-up must either make it required or delete

phase spent two plans removing. File that follow-up in `.planning/HANDOFF.json`
`open_items`.

Verify: `actionlint` or equivalent YAML validation passes, and the diff shows
