# Phase KPL-03 — UI Design Contract

> Visual and interaction contract for Keepling for Mac. Generated by `gsd-ui-researcher`; the checker upgrades this draft after all seven dimensions pass.

---

## Design Intent

Keepling for Mac is a quiet, always-available personal workspace: Things-like in speed and restraint, but more explicit about what is only a draft, what is durable on this Mac, what the server accepted, and what needs recovery. Native Mac fit outranks pixel parity with Keepling Web. Component meaning, task semantics, recovery language, semantic tokens, and focus safety do not drift between the two clients.

The primary window feels like a familiar Mac sidebar/list/detail application, not a browser in a frame or a synchronization dashboard. Routine local saves and healthy synchronization stay silent or brief. Actionable exceptions remain visible beside the affected task and in one bounded Sync & Recovery surface. A visually calm state must never conceal data that is not durable, a conflict, an authentication fence, or an unrecoverable local-store problem.

The Phase 1 palette remains an approved product-token baseline, not a final brand or icon decision. Phase 3 does not specify a new logo, wordmark, mascot, or palette. Brand is concentrated in the application icon, selection marker, focus ring, empty-state tone, and a few meaningful state transitions; native titlebar, traffic lights, menus, typography, and platform behaviors remain recognizably macOS.

Sources: `03-CONTEXT.md` D-01–D-25 and D-39–D-48; `REQUIREMENTS.md` MAC-01–05 and QUAL-03–04; approved `01-UI-SPEC.md`; `docs/brand/BRAND-SEED.md`; `packages/design-tokens/tokens.json`; detected `apps/web/components.json`.

## Main Window Contract

### Window and titlebar

- Use one native, resizable, restorable primary window with standard traffic lights and no custom or frameless titlebar. Default bounds are 1180×780px, centered on the active display on first launch; minimum bounds are 680×520px.
- Restore only validated on-screen bounds, fullscreen state, sidebar visibility, pane sizes, destination, surviving selected task, semantic list scroll anchor, and recoverable editor draft. Clamp invalid bounds into the visible work area with at least the titlebar reachable.
- Use the title pattern `Keepling — destination`, substituting only the coarse destination name: Inbox, Today, Trash, Settings, or Sync & Recovery. It never contains a task title, note, project/tag value, account identifier, server URL, pending-change identifier, or conflict text.
- Closing the primary window resolves dirty work and then destroys or hides the renderer while the resident main-owned application continues. Dock activation recreates the window from durable state. `Command-H` uses native hide; a second launch activates this instance.

### Navigation, list, and detail

- At 1064px and wider, use the inherited three-region composition: 224px navigation, a 360–440px task list, and a flexible detail region with a 480px minimum content area and 720px maximum form measure.
- At 1024–1063px, collapse navigation into a drawer while preserving the 360px list and 480px detail minimums. Below 1024px, show one routed surface at a time; Back returns to the originating list, stable task focus, and semantic scroll anchor.
- List focus and task selection are separate. Up/Down moves stable list focus; Return selects/opens the focused task; Escape from detail returns to its originating list context; Tab follows ordinary control order.
- List and detail scroll independently. Selecting, refreshing, remotely removing, completing, trashing, restoring, or recreating a window preserves focus by stable task identity, never DOM position. After removal, focus the next row, then previous row, then the list heading.
- The list/detail divider has a 1px visible separator and an 8px hit zone. It is keyboard focusable as a vertical separator: Left/Right changes the list width by 16px, Shift+Left/Right by 32px, and double-click resets to 400px. It cannot violate 360/440px list bounds or the 480px detail minimum and displays the standard resize cursor plus visible focus ring.

### Toolbar

Use one quiet toolbar below/within the native titlebar region: sidebar toggle at the leading edge, destination title, then trailing New Task and Sync & Recovery controls. The toolbar never contains task content. Lucide icons are 18px; frequent actions include visible text when space permits and always retain action-and-object accessible names. No essential action is hover-only.

The Sync & Recovery control stays visually neutral while healthy. After the 3-second grace period, it may show `Updating…` with a nonspinning directional indicator. Actionable conflict/authentication/rejection/unrecoverable states add a text label and bounded count; color or a badge alone is insufficient.

## Quick Entry Contract

- `Command-N` opens focused in-app capture. The configurable global shortcut, default `Control-Option-Space`, opens one title-first utility window while Keepling is running. Both invoke the same main-owned semantic capture operation.
- Quick Entry defaults to 520×228px, permits 420–640px width and up to 360px height for validation/recovery copy, uses a native utility-window surface, and is titled `Keepling Quick Entry` without showing task text in the app switcher or Window menu.
- Visual order is title field, `Destination: Inbox`, optional `Add to Today`, then `Add Task`. Title focuses on open. `Command-Return` commits. Standard text editing, non-US layouts, dead keys, and IME composition take precedence over application shortcuts.
- Successful local commit closes/hides Quick Entry and restores focus to the previously active application without waiting for the network. Its durable task appears immediately in Keepling. Failure to commit locally keeps the window and draft open and names the next safe action.
- Escape or `Command-W` hides a nonempty Quick Entry while retaining its durable draft. Only `Discard Draft…` removes it; nonempty discard uses an alert dialog with initial focus on `Keep Draft`.
- Shortcut registration failure is persistent in Settings and Sync & Recovery: `Quick Entry shortcut isn’t available.` Action: `Change Shortcut…`. Never silently fall back to a different shortcut.

## Core Interaction Contracts

### Capture, edit, and lifecycle

- A recoverable draft is not a task change. `Saved on this Mac` appears only after visible projection plus immutable command/journal/dependencies/outbox commit atomically. `Synced` appears only for the exact matching server acknowledgement and is never inferred from connectivity or another lane.
- In-app capture and edit preserve title, notes, project, tags, planned date, deadline, Inbox intent, and Today intent according to the shared semantic contract. Task content is always plain text. Planned date and deadline remain separate.
- Editor actions are `Save Changes`, `Cancel Editing`, and, for Inbox, `Save & Move Out of Inbox`. `Command-S` and `Command-Return` save. Escape, navigation, window close, and quit with dirty work use `Save Changes`, `Discard Changes`, and safe-default `Keep Editing`; there is no save-on-blur.
- Local save keeps the resulting task/row visible immediately. Routine confirmation `Saved on this Mac` is brief; when offline or delayed, add `Sync when you’re back online` or `Pending change` only where useful.
- Complete/reopen, Trash/restore, Today placement/order, and supported undo use the same local-first acceptance threshold. Move to Trash has no preconfirmation because it is recoverable; after local commit show `Task moved to Trash. Undo Trash` in the persistent recovery strip.
- Only the latest eligible semantic undo is persistent across routes. `Command-Z` remains text undo whenever an editable control owns focus; semantic undo is the named menu/visible action.

### Focus and announcements

- Use logical landmarks/groups for navigation, list, detail, Quick Entry, Sync & Recovery, settings, and recovery shell. Use native headings, lists, forms, buttons, labels, checkboxes, separators, and dialogs; never a custom ARIA grid.
- Focus is visually distinct from selection. Every renderer control has a 2px accent focus ring with 2px offset, unclipped by pane overflow. Selected navigation also uses an edge and weight; selected task also uses row geometry/semantics.
- Dialogs and drawers trap focus only while modal and return it to their trigger. Consequential dialogs initially focus the safe action. The inline conflict resolver focuses its heading, then returns to the initiating Save action or first affected field.
- Each window owns one debounced polite live region for meaningful transitions. Batch repeated acknowledgements into a bounded summary such as `3 changes saved on this Mac`; never announce every sync acknowledgement. Authentication and unrecoverable local-store failures may use an assertive announcement once without stealing focus.

## Synchronization and Recovery Presentation

### Hierarchy

1. Healthy synchronization is silent.
2. Work still active after 3 seconds appears as `Updating…` in the toolbar control.
3. Affected tasks show a compact, text-backed local state only when pending is prolonged or actionable: `Pending Change`, `Conflict`, or `Review`.
4. Deliberate inspection opens a 400px-wide anchored popover at 1024px+ and a modal drawer below 1024px. It is titled `Sync & Recovery`, is capped at 70% of window height, scrolls internally, and never becomes an admin event log.
5. Migration, integrity, permission, read-only, or local-store open failure replaces the workspace with the narrow recovery shell. It never renders a false empty task list or silently creates a new store.

All shell, row, and panel summaries come from one authoritative main-owned semantic presentation projection with closed states, bounded counts, coarse times, and named recovery actions. The renderer never infers truth from an online flag, socket, timer, progress animation, or absence of an error.

### Exact state language

| State | Presentation | Action |
|-------|--------------|--------|
| Opening local state | `Opening your tasks…` over the stable workspace frame; no empty state | None |
| First local preparation | `Preparing your tasks for offline use…` | None; never perpetual |
| Ordinary catch-up beyond grace | `Updating…` while accepted local content remains interactive | Open Sync & Recovery |
| Offline last-good | `Offline — showing tasks saved on this Mac` | None unless retry is actionable |
| Retryable server failure | `Couldn’t reach the server. Your changes stay on this Mac.` | `Retry` |
| Local acceptance | `Saved on this Mac` and, when useful, `Sync when you’re back online` | None |
| Uncertain server result | `Checking whether this change was accepted…` | `Check Again` |
| Rejection | `The server didn’t accept this change. Your version is still on this Mac.` | `Review` |
| Conflict | `This task changed somewhere else. Choose what to keep.` plus `Other tasks can continue.` | `Review Conflict` |
| Authentication fence | `Sign in to continue syncing. Changes remain safe on this Mac.` plus bounded pending count | `Sign In` |
| Namespace mismatch | `These changes belong to a different account or server and won’t be sent here.` | `Inspect`, `Export`, then separately confirmed removal |
| Local save failure | `Couldn’t save this change on this Mac. Nothing was added to your task list.` | A specific action such as `Free Storage and Try Again` or `Retry Saving` |
| Local store unavailable | `Keepling can’t open the tasks saved on this Mac. Your data was not replaced or removed.` | `Retry Opening`; `Show Recovery Options` |

Never say `Everything synced` from one successful lane. The healthy panel may say `No changes need your attention` and show coarse copy such as `Last successful contact: 8 minutes ago`, but it does not claim global completeness. Never use backend words such as outbox, cursor, SQLite row, fingerprint, bootstrap, or transport retry in primary copy.

### Conflict resolver

Conflicts stay inline above the task form and survive route/window recreation. Show only affected fields with labeled `Your Version` and `Current Version`, plus `Use Mine` and `Use Current`. Preserve all nonconflicting draft fields. `Keep Editing` returns without mutation. Resolution uses a fresh semantic command against current server truth; no choice is inferred from color or recency. Notes longer than six lines use a keyboard-operable `Show Full Value` disclosure.

## Copywriting Contract

Use sentence case in renderer controls and macOS title case in native menus. Copy is compact, concrete, non-blaming, and explicit about what is durable and what did not happen.

### Primary and form actions

| Element | Exact copy |
|---------|------------|
| Global primary CTA | `New Task` |
| Capture prompt | `What do you want to keep?` |
| Capture destination | `Destination: Inbox` |
| Optional placement | `Add to Today` |
| Capture commit | `Add Task` |
| Editor primary | `Save Changes` |
| Inbox clarification | `Save & Move Out of Inbox` |
| Editor secondary | `Cancel Editing` |
| Reauthentication | `Sign In and Continue` |
| Recovery inspector | `Sync & Recovery` |

### Empty states

| View | Heading | Body / next step |
|------|---------|------------------|
| Inbox | `Inbox Is Clear` | `Captured tasks appear here until you move them out.` — `New Task` |
| Today | `Nothing for Today` | `Add a task or choose an existing task to make it part of today.` |
| Trash | `Trash Is Empty` | `Tasks moved to Trash stay recoverable here.` |
| No selected task | `Choose a Task` | `Select a task from the list to view or edit it.` |
| Sync & Recovery, no actionable state | `No Changes Need Your Attention` | Show coarse last successful contact; do not claim everything is synced |

Opening, preparing, updating, and failed-loading states never reuse empty-state copy.

### Destructive and consequential actions

| Action | Confirmation approach and exact copy |
|--------|--------------------------------------|
| Move one task to Trash | No preconfirmation; after local commit show `Task moved to Trash. Undo Trash` persistently |
| Discard editor changes | Heading `Discard Unsaved Changes?`; body `These edits haven’t been saved.` Actions `Save Changes`, destructive `Discard Changes`, safe `Keep Editing`; initial focus `Keep Editing` |
| Discard Quick Entry draft | Heading `Discard Quick Entry Draft?`; body `This draft is saved on this Mac but hasn’t been added as a task.` Actions destructive `Discard Draft`, safe `Keep Draft`; initial focus `Keep Draft` |
| Remove data from this Mac, no local-only intent | Heading `Remove Data from This Mac?`; body `This removes local tasks, drafts, and sign-in from this Mac. It does not delete server data.` Actions `Remove Data`, safe `Keep Data`; initial focus `Keep Data` |
| Remove data with pending/conflicted intent | First show bounded counts and `Sync First` where possible. Second heading `Remove Local Changes Anyway?`; body `These changes have not been accepted by the server. Removing them from this Mac cannot be undone.` Actions destructive `Remove Anyway`, safe `Keep Data`; initial focus `Keep Data` |
| Namespace-mismatched local data | Require `Inspect` and offer `Export` before the same two-step removal flow; never merge or send it to the current namespace |
| Sign out | Fence the namespace and preserve its local intent; if editor/Quick Entry is dirty, resolve the draft with the corresponding safe dirty-work dialog first |

There is no server hard-delete, local cryptographic-erasure claim, bulk task deletion, or routine OS notification in Phase 3.

## Accessibility and Platform Contract

- Meet WCAG 2.2 AA for the renderer and pass VoiceOver plus Full Keyboard Access for Quick Entry, capture, Inbox, Today, edit, complete/reopen, Trash/restore, undo, conflict resolution, authentication recovery, Sync & Recovery, settings, dirty close, window recreation, and local-store recovery.
- Test at 200% zoom/reflow, Increase Contrast, Differentiate Without Color, Reduce Transparency, Reduce Motion, forced colors, and light/dark changes while the app and dialogs are open. At minimum width, no surface requires two-dimensional scrolling.
- Every icon-only action has an action-and-object name such as `Complete “Call dentist”`, `Open actions for “Call dentist”`, `Show Sync & Recovery`, or `Restore “Call dentist”`. Window/menu titles never leak the quoted task content.
- Non-US layouts, IME/dead keys, shortcut collision/rebinding, key repeat, and text-control ownership are release evidence. Application shortcuts do not consume composition events or standard macOS editing commands.
- Completion, pending, conflict, selected navigation, selection, warning, error, authentication, and destructive intent remain understandable without color, sound, hover, or motion.

## Motion

Use 140ms ease-out for direct hover/focus/selection acknowledgement and at most 180ms for drawers, popovers, and dialog appearance. Local capture may settle with opacity plus no more than 4px translation; completion/restore may use the same restrained movement. Synchronization does not use a perpetual spinner; a static directional icon plus text is sufficient after the grace period.

Under Reduce Motion, state changes are immediate or use opacity no longer than 100ms. Disable smooth scrolling, row translation, skeleton pulsing, drag animation, and decorative transitions. No durability, selection, conflict, or error meaning depends only on animation.
