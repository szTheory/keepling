## Why browser-delegated, and not an in-app sign-in form

`/oauth/authorize` is `pipe_through [:api, :authenticated]` — it requires an existing browser
session. That is the design, not an obstacle. Authenticating in the system browser rather than in
an Electron window means:

- Whatever authenticates that session — Argon2id password today, passkeys/SSO/MFA later (Sigra is
  the intended eventual owner; see the roadmap item) — the desktop needs **zero** changes.
- Passkeys work, because WebAuthn platform-authenticator support lives in the browser. Electron's
  own macOS platform-authenticator support is incomplete; delegating avoids it entirely.
- Password-manager autofill works properly, which it does not reliably inside an Electron window.

A private-use scheme (`keepling://auth/callback`) is used rather than an RFC 8252 loopback redirect
because the server's `allowed_redirect?/2` is an exact-match allowlist and loopback requires an
ephemeral port.

<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| System browser → desktop (`keepling://`) | Any local app may register the same scheme; callbacks are untrusted input. |
| Desktop → server (`/oauth/*`, `/api/v1/sync`) | Public client with no secret; possession of a code must not be sufficient. |
| Renderer → main (account IPC) | Renderer must not hold credentials or reach the network directly. |

## STRIDE Threat Register — ASVS Level 1
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-KPL03-14-01 | Spoofing | `keepling://` scheme | high | mitigate | PKCE S256 makes an intercepted code unusable without the verifier; state is matched against exactly one in-flight request; the server enforces a short code TTL and single use. |
| T-KPL03-14-02 | Tampering | namespace tuple | high | mitigate | All five fields are stored verbatim from the token response; no client-side assertion, derivation, or default. |
| T-KPL03-14-03 | Information disclosure | token storage | high | mitigate | Tokens persist only through `SafeStorageCredentialAdapter`; no renderer path can read them. |
| T-KPL03-14-04 | Repudiation | refresh rotation | medium | accept | Server-side replay detection and family absolute TTL already exist in `device_grant.ex`; this plan surfaces `refresh_replay_detected` as a recovery presentation rather than a silent retry. |
| T-KPL03-14-05 | Denial of service | boot configuration | medium | mitigate | Fail-fast configuration validation converts a silent runtime 400 into a named boot failure. |

**Known residual, disclosed:** private-use-scheme registration is first-come on macOS and cannot be
exclusively claimed. PKCE plus state matching reduce this to a denial-of-service (a competing app can
intercept a callback but cannot exchange it). This is disclosed, not silently accepted.
</threat_model>
