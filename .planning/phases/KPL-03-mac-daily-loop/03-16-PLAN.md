<design_guidance>
The measured facts, established before this plan was written:

* `apps/desktop/main/index.ts:690` constructs `QuickEntryWindowController` with
  `desktopApplication`, `preloadPath` and `rendererUrl` only.
* `quick-entry-window.ts:187,195` call `captureActiveApp()`; `:239` (inside
  `hide()`) calls `restoreActiveApp(handle)` only when the handle is non-null.
* The sole implementation is `RecordingForegroundAppPort` in
  `test/fixtures/wired-app-harness.ts:59`, which appends to a string log.
* Row A9 (`tooling/verify-macos-integration.mjs:1479`) opens a real prior
  application, places its caret at a known non-zero offset, invokes Quick Entry
  by real global shortcut, and after close asserts BOTH that
  `frontmost.bundleIdentifier` is the prior application AND that the caret
  offset and length are unchanged. It does this twice: `submitted` (Return) and
  `discarded` (Escape).

RECOMMENDED APPROACH -- `app.hide()`, verified empirically, not assumed:

macOS returns activation to the previously active application when an app
hides itself, and it does so without any TCC permission and without a native
module. That makes `Electron.app.hide()` the natural `restoreActiveApp`, and it
preserves the prior application's caret for free, because that application is
reactivated rather than re-opened.

`captureActiveApp()` therefore does not need to identify the other application
at all. It only needs to record whether KEEPLING was frontmost when Quick Entry
was invoked, which is answerable from Electron alone (for example via
`BrowserWindow.getFocusedWindow()` at capture time). Return an opaque handle
carrying that one boolean -- the port's contract is deliberately opaque, so do
not widen it to leak a bundle identifier.

`restoreActiveApp(handle)` then branches:
  * Keepling was NOT frontmost -> `app.hide()`; activation returns to the prior
    application. This is the A9 path.
  * Keepling WAS frontmost -> do not hide. Focus the main window instead, so
    invoking Quick Entry from Keepling itself does not make the app vanish.

This approach is a recommendation grounded in the row's requirements, not a
constraint. Verify it by running row A9. If measurement contradicts it, deviate
and record why in the SUMMARY -- but the prohibitions above still bind, in
particular the ban on an Automation (AppleScript) prompt in the shipped path
and the ban on relaxing A9.

Note that `hide()` sets `#capturedForegroundHandle = null` BEFORE awaiting the
restore, so a second invocation re-captures. Preserve that ordering.
</design_guidance>
