## Critical Anti-Patterns

| anti-pattern | severity |
|---|---|
| Bulk-exporting the login keychain (`security export -t identities`) to obtain the `.p12`. It decrypts **every** identity, including the owner's employer's certificate, and macOS names the employer in the resulting prompt. This already happened once and was caught by the owner. Export exactly one identity via Keychain Access, or hand him the step. `tooling/local/publish-signing-secrets.sh` refuses any bundle holding more than one certificate. | blocking |
| Writing the owner's personal email, legal name, team ID, or employer name into a committed file or commit message. All 51 commits are currently clean and authored as `szTheory <szTheory@users.noreply.github.com>`. This repository is headed for a public Apache-2.0 release; published bytes cannot be recalled. Scripts must read these values at runtime from 1Password or from the certificate. | blocking |
| Claiming the Mac app is signed or notarized, or that the server OCI image is signed, anywhere in the trust documents before those things are actually true. The whole phase's discipline has been no-overclaim; QUAL-02 was deliberately left unchecked three separate times for this reason. | blocking |
