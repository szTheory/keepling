<objective>
**User story:** As a Keepling user on my Mac, I want a change the server refused to still be mine
afterwards, so that an edit I made and saw accepted locally is never silently replaced by the
server's older value on the next sync.

`apps/desktop/store-worker/local-store.ts` currently carries a comment in shipped code stating that
a refused command is terminal, is gone from the outbox, and that the next pull replays the shadow
and the local value is lost. The product's stated core value is that accepted changes are never
silently lost or overwritten. A phase named "Trust Release" cannot ship over that.

Purpose: close the open data-loss class named by D-37, at the storage layer where the loss happens.
Output: a durable refusal table covering every refusal outcome, and a replay path that refuses to
overwrite an unresolved refusal.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server pull → local projection | The server's view crosses into local storage and can replace a value the person authored; this is the boundary where the loss occurs. |
| local refusal record → conflict resolver | The record is the only remaining representation of the person's refused value; if it is malformed the value is unrecoverable. |
| local refusal record → trust oracle | The oracle's refusal-durability invariant reads this table as ground truth about whether a refused change had a home. |
