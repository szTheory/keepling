  <name>Task 1: Confirm the published archive format and its version contract</name>
  <files>(no files — this task is a decision gate; the dependent task writes the files)</files>
  <decision>
    Confirm that Keepling's export bundle format and its versioning contract are fixed as 06-CONTEXT.md
    D-02, D-03 and D-04 specify, before any file is written in that shape.

    **The proposal on the table (D-02/D-03/D-04):**
    - A zip bundle containing `manifest.json`, one `data/<entity>.ndjson` per entity type,
      `FORMAT.md`, and a human-readable `tasks.md`.
    - The schema lives in `packages/contracts/schemas/export/` as its own JSON Schema set, NOT as a
      reuse of `packages/contracts/openapi/keepling.yaml` shapes.
    - Versioning is a standalone integer `export_format_version` in `manifest.json`, starting at 1,
      decoupled from OpenAPI and from protocol trains, additive-only within a version, with no
      age-out ever. `keepling_version` and `generated_at` are provenance only; readers key off
      `export_format_version` alone.

    **Why this is a one-way door.** The wire protocol is deliberately allowed to evolve on protocol
    trains with age-out. An archive format may never age out: the compatibility promise attaches to
    files already sitting on users' disks. A user's five-year-old bundle is written in whatever is
    decided here, and it cannot be rewritten after the fact.

    **Pros of the proposal.** NDJSON is streamable in both directions so memory stays bounded; per-line
    tools work; line-oriented diffs are meaningful; one corrupted byte does not destroy the archive;
    `tasks.md` is readable with no tooling at all, which is literally what "inspectable without
    Keepling internals" means. Prior art converges here (1Password `.1pux`, Google Takeout, Joplin
    JEX, Day One). A standalone integer version buys the drift gating of `pnpm contracts:check`
    without coupling the archive's lifetime to the protocol's.

    **Cons and what was rejected, with reasons.** A single JSON document was rejected for unbounded
    memory and catastrophic single-byte corruption. SQLite was rejected because it needs a tool and
    re-exports internals. CSV-only was rejected as lossy for nested actor records. iCalendar VTODO
    was rejected because RFC 5545 plus RFC 9253 cannot carry inbox state, activity, agent actors, or
    the independent planned/deadline pair — adopting it would lose data.

    **The undo cost if wrong.** Changing the bundle shape later means either a second reader, a
    permanent compatibility branch, or telling users their old bundles are unreadable. There is no
    migration for a file you do not control.
  </decision>
  <context>
    No code has been written in this shape yet, so this is the last cheap moment. Everything
    downstream — plan 06-08's golden vector and independent reader, the `FORMAT.md` a user reads,
    and the public portability claim in plan 06-11's policy documents — is written against whatever
    is confirmed here.
  </context>
  <options>
    - **Confirm as proposed (recommended).** Proceed with the zip + NDJSON + standalone schema +

    - **Change the container or the file split.** State the alternative; the executor re-derives the

    - **Change the versioning contract.** For example couple it to protocol trains after all, or

  </options>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI → application command | The export verb crosses the Ops envelope into inward application code; it must not become a second path that bypasses domain invariants. |
| database snapshot → plaintext file on disk | The bundle is the richest plaintext artefact the product produces, written outside the database's access controls. |
| agent / MCP surface → export capability | An agent-reachable export would be a complete exfiltration primitive. |
| published archive format → future readers | A format decision binds files already on users' disks. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-04-01 | Information Disclosure | agent-triggered export | critical | mitigate | `AgentScope`'s closed three-string whitelist cannot express an export scope and `require/2` admits only whitelist members; the export has no MCP adapter. A regression pins both properties so a future scope addition breaks the test rather than the boundary. |
| T-06-04-02 | Information Disclosure | the written bundle on disk | high | mitigate | Owner-only file permissions on the bundle; `FORMAT.md` and the operator output state plainly that it is unencrypted and is not a backup; no at-rest encryption is invented. Residual exposure to anyone with the operator's filesystem access is accepted and disclosed rather than hidden. |
| T-06-04-03 | Information Disclosure | credential material leaking into the access inventory | high | mitigate | The access inventory exports metadata only; `classification.json` marks every hash and token column `out`, and plan 06-08's no-secrets assertion greps the produced bundle for known credential fixtures. |
| T-06-04-04 | Tampering | a silently truncated bundle presented as complete | high | mitigate | `manifest.json` is written last and carries per-file sha256 and row counts, so a truncated bundle fails its own validator; the distinct `:export_query_timeout_ms` removes the mandatory-positive-timeout footgun that would truncate a large read. |
| T-06-04-05 | Denial of Service | unbounded memory or a long-held transaction on a small single-host VM | medium | mitigate | `Repo.stream` with an explicit `max_rows` chunk size bounds memory; the verb is operator-only with no network surface, so it cannot be an amplification target. |
| T-06-04-06 | Repudiation | an export happening with no record | medium | mitigate | One `security_audit` event per export, using the existing closed event vocabulary. |
| T-06-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install occurs in this plan; the export is built on already-pinned Ecto. RESEARCH.md's Package Legitimacy Audit records no assumed, suspicious or fabricated package for this phase. |
</threat_model>
