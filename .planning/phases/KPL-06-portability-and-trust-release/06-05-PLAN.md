<objective>
**User story:** As Keepling's maintainer, I want the same semantic commands proven against all four
adapters — browser, agent, Mac and iPhone — so that "one set of semantic invariants across adapters"
is a measurement rather than a promise deferred for a fourth time.

Two of the four legs already pass with matching comparisons across all four shared scenarios. The
remaining work is drivers, not scenarios: both harnesses already exist and this plan wires them in.

Purpose: SRV-02 has been deferred by three consecutive phases; deferring again would make "Phase 3
complete" and "Phase 4 complete" rest on a promise never kept.
Output: a live Electron driver, a live iPhone driver, an extended guard list, and either a
four-green lane or an honestly disclosed, owned, non-passing one.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test driver → shipped application | A driver that needs a hook inside the product turns a test requirement into a shipped attack surface. |
| leg self-report → cross-adapter comparison | If a leg's own claim were the comparison source, the lane would prove nothing about agreement. |
| lane evidence → SRV-02 checkbox | The blocked-leg count decides whether a requirement may be marked satisfied. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-05-01 | Elevation of Privilege | a test-only affordance inside the shipped iOS app | critical | mitigate | Adding one is forbidden by this plan's prohibition and checked by an acceptance criterion asserting `git diff apps/ios/` adds no command, endpoint or gated hook; the honest alternative is a disclosed blocked leg. |
| T-06-05-02 | Spoofing | a driver shortcut — stubbed fetch, placeholder host, injected bearer, test-only sync mode | high | mitigate | Both new driver files are added to `verify-cross-adapter-phase.mjs`'s `GUARDED_FILES` and `TRACKED_INPUT_PATHS`, so the guard-refusal checks run against them at every invocation, not once at authoring time. |
| T-06-05-03 | Repudiation | a blocked leg quietly reported as a skip | high | mitigate | BLOCKED keeps the overall exit non-zero, a leg reporting zero cases fails the gate, and `legs_blocked` is an explicit reported field that SRV-02's checkbox is gated on. |
| T-06-05-04 | Information Disclosure | a disposable Electron profile left behind with real session material | medium | mitigate | The driver removes the disposable profile directory on both success and failure paths. |
| T-06-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install occurs in this plan; both drivers are Node scripts built on already-present tooling. RESEARCH.md's Package Legitimacy Audit records no assumed, suspicious or fabricated package for this phase. |
</threat_model>
