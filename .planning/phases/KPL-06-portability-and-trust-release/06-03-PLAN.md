<objective>
**User story:** As someone who finds Keepling on GitHub, I want the repository to actually grant me
the rights its README claims, so that I can use, modify and redistribute it without guessing.

This is the live misrepresentation named by D-54(2): the README claims a complete open-source
personal product and the repository grants no rights at all. It is also a hard ordering
dependency — CycloneDX component license fields are populated from exactly these metadata strings,
so the SBOM in plan 06-10 would record unknown licenses if it ran first.

Purpose: close the rights gap and populate the metadata the supply-chain work reads.
Output: LICENSE, NOTICE, and a license declaration in every package manifest.
</objective>

<task type="checkpoint:decision">
  <name>Task 1: Confirm the licence before it is granted to anyone who clones</name>
  <files>(no files — this task is a decision gate; Task 2 writes the files)</files>
  <reversibility rating="one-way">A licence cannot be retracted from copies already distributed, and every future contributor's inbound grant is defined by it.</reversibility>
  <decision>
    Confirm that Keepling is released under the Apache License 2.0, uniformly across the entire
    monorepo, before the licence file is committed. This was answered by the owner on 2026-09-11
    (D-24); the checkpoint exists because the phase context instructs that every decision marked
    one-way be raised before the task implementing it, and because this is the single least
    reversible act in the phase.

    **Why it is one-way.** The moment a clone exists, the rights granted in it cannot be withdrawn.
    Every later contribution is made under whatever is chosen here, and relicensing afterwards
    requires every contributor's consent.

    **The recorded rationale for Apache-2.0.** It matches the author's newer library convention on
    the public package registry. Its explicit patent grant with defensive termination is material for
    a codebase shipping a hand-rolled authorization server, proof-key exchange, refresh rotation and
    a password hash. Its trademark clause withholds naming rights, protecting the project name
    without a separate policy. Its contribution clause makes inbound contributions same-terms
    automatically, which removes the main reason to want a separate contributor agreement. And it
    leaves every future option open: a hosted service, App Store distribution, dual-licensing, or an
    acquisition.

    **What was rejected and on what concrete ground.** A strong-copyleft network licence was rejected
    because its terms conflict with the mobile store's usage rules — the iPhone client is shippable
    today only because the author is sole copyright holder, and the first outside contributor to
    touch shared code would make store distribution require their permission permanently. The
    source-available licences were rejected because the project's own README claims a complete
    open-source product, and a non-approved licence under that sentence is precisely the overclaim
    this project's culture exists to prevent.

    **The flip condition, requiring both halves and true today of neither:** a hosted service becomes
    the primary revenue model AND the iPhone client is permanently distributed outside the store.
  </decision>
  <context>
    Nothing is committed yet. Confirming here is the last cheap moment; after the first clone it is
    not a decision any more. Uniform means no per-package reasoning ever — the usual instinct to make
    a client library more permissive exists to fix copyleft friction that this licence does not have.
  </context>
  <options>
    - **Confirm Apache-2.0, uniform across the monorepo (the owner-answered choice).**
    - **Choose a different licence.** State it; the rationale above, the contributor-agreement decision
      in plan 06-11, and the store-distribution consequence all have to be re-derived against it.
    - **Defer.** The repository continues to grant no rights while claiming to be open source, which is
      the live misrepresentation this plan exists to close; if deferred it becomes a disclosed
      limitation with a named owner, never a silent gap.
  </options>
  <resume-signal>Reply `confirm` to proceed with Apache-2.0, or name the licence you want instead.</resume-signal>
  <done>The licence is explicitly confirmed or replaced, and the decision is recorded in the plan summary before Task 2 writes the file.</done>
</task>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository → downstream redistributor | `LICENSE` and `NOTICE` are the only artefacts defining what a fork may do; NOTICE content is reproduced by every distributor forever. |
| package metadata → generated SBOM → release consumer | A consumer reads component licences from the SBOM, which reads them from these manifest strings. |
| Hex registry → build environment | A new Mix dependency enters the build toolchain. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-03-01 | Repudiation | `LICENSE` absence | high | mitigate | Verbatim Apache-2.0 committed at the repository root; the governance lane in plan 06-11 hashes it against the canonical text, so a silent edit is detectable. |
| T-06-03-02 | Tampering | `NOTICE` content growth | medium | mitigate | An automated line-count ceiling of 6 fails the task if NOTICE accumulates sticky content that every fork would then be obliged to reproduce. |
| T-06-03-03 | Spoofing | SBOM component licence fields reading `UNKNOWN` | high | mitigate | All four `package.json` files and `mix.exs` declare the licence before the SBOM is generated (D-54 ordering), and the check asserts all four were inspected. |
| T-06-03-04 | Tampering | new Hex dependency `:sbom` in the build toolchain | high | mitigate | Scoped `only: :dev, runtime: false`; a `MIX_ENV=prod mix compile` gate proves it cannot reach a production build; the package was verified against the hex.pm registry API (maintainer `erlefsecuritywg`) rather than assumed. |
