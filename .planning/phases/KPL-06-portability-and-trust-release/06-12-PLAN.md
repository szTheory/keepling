<objective>
**User story:** As Keepling's owner, I want the absence of data-loss, silent-overwrite and
recovery-severity defects to be measured on my real installation, so that "no unresolved defects"
stops being an assumption I make about my own product.

The existing dogfood contract already ruled that sustained daily use is not automatable and is not a
gate, that nobody signs off on it and nothing counts it. **That ruling stands and this plan does not
touch it.** What it left open is that the defect-absence half was never measured by anything — and
the tell is that the two silent-class defects this phase is closing were both found by code review
and probes, not by using the application.

Purpose: turn a defect-absence assumption into a measurement with a stated floor and a stated blind
spot.
Output: a read-only reconciliation oracle, eight invariants, a chaos corpus, a usage census, and a
gate that refuses an oracle it cannot prove detects corruption.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| checker → observed systems | A checker with any write authority becomes a new source of the loss it exists to detect. |
| oracle output → diagnostic artefact | Violation records are diagnostic output and fall under the product's no-raw-content privacy constraint. |
| evidence artefact → release decision | The artefact decides whether a release criterion may be claimed; a chooseable window or a resettable clock would make it a formality. |
| informal owner feedback → evidence | Feedback becoming an evidence row would conflate preference with correctness. |
