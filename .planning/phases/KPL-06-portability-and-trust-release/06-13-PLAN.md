<objective>
**User story:** As Keepling's maintainer at the end of the milestone, I want one command that says
whether this exact revision may be released and on what evidence, so that the release claim is
something a third party can re-check rather than something I assert.

Everything before this plan produced a lane. This plan closes the inventory over all of them, runs
the whole release verification against one revision, retains the evidence, and disposes every
requirement claim honestly — flipping only what a passing lane supports and disclosing the rest with
an owner.

Purpose: make the release claim checkable, and make every remaining gap owned.
Output: a complete lane inventory, a verified and retained release manifest, and a requirement
ledger where every claim is either backed by a positive-count lane or disclosed with an owner.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| lane evidence → requirement checkbox | A checkbox is the project's public claim; flipping one without supporting evidence is the failure mode this whole phase exists to correct. |
| committed inventory → release verifier | The closed inventory is the only reason a vanished lane is detectable rather than invisible. |
| locally attested lane → continuous-integration artefact | Without the digest binding, any failing lane could be moved local to make it green. |
| expiring build artefact → retained evidence | Evidence that expires cannot support a claim made after it expires. |
