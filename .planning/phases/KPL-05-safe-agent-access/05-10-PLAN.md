<objective>
Build the gate this phase's claims will rest on, and build it distrustfully.

Phase 4 shipped twenty-one green lanes over stubs, fakes, and a SQLite fixture committed in its
post-migration state, so its central assertion was tautological on every checkout. Five subsequent
verifier passes then found skipped cases published as executed, a counter that discarded whole test
bundles — on one lane the discarded bundle was the only hardware evidence and contributed zero to
the published number — and a composite of three separate runs written up as one passing gate.

This phase is about agent safety. The same class of failure here would be considerably worse,
because the thing being falsely claimed is that a language model cannot escalate its own authority.

Purpose: SRV-02 and success criterion 5 depend entirely on this runner meaning what it says.

Output: `tooling/verify-mcp-phase.mjs` with the anti-vacuity structure, a test of the harness
itself, and the first two lanes.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Lane process output → published case count | The boundary where a false claim about evidence would be created |
| Git-tracked inputs → lane verdict | Provenance boundary: a verdict must name what it examined |
| Runner exit status → the phase's completion claim | The boundary a reader trusts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-51 | Repudiation | `exUnitSummary` | critical | mitigate | Every invocation's summary is anchored and summed, skips subtracted, zero-case invocations throw; the self-test asserts the exact counts window 65 recorded as undercounted |
| T-05-52 | Repudiation | blocked lanes | critical | mitigate | The blocked prefix is the only discriminator, blocked is printed distinctly, and a blocked lane still sets the failure flag so the run exits non-zero |
| T-05-53 | Repudiation | lane omission | high | mitigate | Lanes are discovered by glob and a failed import ends the run; a lane cannot vanish by being forgotten or by failing to load |
| T-05-54 | Tampering | evidence provenance | high | mitigate | Each verdict carries a `git ls-files`-derived content digest of the inputs the lane exercised, so a verdict cannot be attributed to inputs it never saw |
| T-05-55 | Repudiation | composite runs reported as one gate | high | mitigate | A per-run identifier differs between invocations and the summary is written once per process; the self-test asserts two runs cannot be presented as one |
| T-05-56 | Spoofing | protocol lane vacuity | high | mitigate | The lane asserts the exact pinned revision string rather than handshake success, closing the first vacuity mode research named |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install occurs in this plan: the runner is plain Node and the self-test uses the built-in `node --test` runner. Any future install proposal requires the package-legitimacy gate and a blocking human checkpoint first |
</threat_model>
