<objective>
Build the one genuinely missing read capability. `grep -rn search apps/server/lib` returns nothing
today, and MCP-01 names search as a required resource. Per D-09, build it as a shared
application-level bounded query with an HTTP endpoint, not as an MCP-only code path — giving MCP a
capability the other adapters lack would falsify SRV-02's "same invariants" claim in the same
commit that proves it.

Purpose: plan 05-04 exposes these as MCP resources. They must exist as ordinary application queries
first, with the same cursor discipline every other bounded view in this codebase already uses.

Output: `Keepling.Application.Search`, `Keepling.Application.Projects`, their Postgres adapters, a
tsvector index, and HTTP endpoints all five adapters can call.
</objective>

  <behavior>
    - `Search.query(context, "milk", opts, port)` returns tasks whose title or notes match, ordered by `(accepted_at DESC, task_id)`, capped at the default limit.
    - Requesting a limit above the maximum is clamped to the maximum, not rejected and not honoured.
    - The returned cursor pages forward without repeating or skipping a row, and remains correct while unrelated tasks are inserted between pages.
    - A cursor issued for query `"milk"` decodes to an error when presented with query `"bread"`.
    - A cursor issued for one account decodes to an error under another account's context.
    - A cursor with a flipped byte decodes to the same single opaque error as a structurally invalid one — no distinguishing signal.
    - Trashed tasks are excluded; completed tasks are included and marked as such.
    - An empty or whitespace-only query term returns an empty page rather than every task.
  </behavior>

Create `Keepling.Application.Search` as a sibling of `TaskViews`, not an extension of it —
`TaskViews.@views` is closed to four named unfiltered views and its cursor shape assumes one
(D-35). Give it its own nested `Port` behaviour with `@callback search_tasks(map(), String.t(),
map()) :: {:ok, map()} | {:error, atom()}`, and `@default_limit 20` / `@maximum_limit 50` matching
`task_views.ex:11-12`.

Copy `encode_cursor/3` and `decode_cursor/3` from `task_views.ex:63-97` verbatim in construction —
`:erlang.term_to_binary/2` with `[:deterministic]`, `:crypto.mac(:hmac, :sha256,
context.cursor_secret, payload)`, `Base.url_encode64/2` without padding; decoded with
`:erlang.binary_to_term(payload, [:safe])`, `:crypto.hash_equals/2` for the MAC compare, and an
account re-check after decode. Where `TaskViews` pins the `view` atom in the payload tuple, pin a
digest of the normalized query term instead, so a cursor cannot be replayed against a different
query. Every failure path collapses to `{:error, :invalid_cursor}`.

and ties are common, so it is not stable under a keyset cursor. Scope every query to
`context.account_id` in the WHERE clause, never only in application code.

Write `apps/server/test/keepling/application/search_test.exs` covering every item in `<behavior>`,

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-13 | Information Disclosure | `Keepling.Adapters.Postgres.Search` | critical | mitigate | Every query carries `account_id` in its WHERE clause; the cursor re-checks the account after decode; a foreign project identity returns not-found rather than an empty page |
| T-05-14 | Tampering | search and project cursors | high | mitigate | HMAC-SHA256 over a deterministically encoded payload, constant-time compare, `[:safe]` term decoding, query digest and project identity pinned so a cursor cannot be replayed across queries |
| T-05-15 | Denial of Service | `websearch_to_tsquery` over a GIN index | medium | mitigate | Hard maximum page size clamped rather than honoured; the existing `hammer` limiter covers the endpoints; a stored generated column keeps the plan index-only |
| T-05-16 | Tampering | the query term | medium | mitigate | The term is passed as a bound parameter to `websearch_to_tsquery`, never interpolated into SQL; an empty or whitespace-only term returns an empty page rather than an unfiltered scan |
| T-05-17 | Information Disclosure | cursor error signalling | low | mitigate | Every decode failure collapses to one opaque error, so a caller probing the cursor format learns nothing |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install occurs in this plan; core PostgreSQL only, with no extension created. Any future install proposal requires the package-legitimacy gate and a blocking human checkpoint first |
</threat_model>
