<objective>
Make agent actions visible and recoverable in the history the user already reads, and make the
privacy guarantee structural rather than filtered.

Two facts discovered while planning shape this plan and save it a migration:
`20260830000500_expand_task_activity.exs:57-61` already admits `actor_type = 'agent'` with
`actor_principal = 'authorized_grant'`, and `:64` already admits `client_kind = 'mcp'`;

vocabulary was anticipated at schema-design time. What does not exist is any code path that sets
it, an undo path proven for agent actions, or a written statement of what the undo claim covers.

recovery, without exposing private chain of thought.

Output: agent attribution proven end to end, a storage-level privacy assertion, a working agent
undo handle, and an honest written scope for the recovery claim.

<task type="checkpoint:decision">
  <name>Task 1: Confirm the storage-level privacy guarantee</name>
  <decision>
D-21 is one-way. Keepling persists no model reasoning, no prompt text, no tool-call rationale, and
no conversation content — only the closed command and the arguments actually executed. This is a
storage-level guarantee: there is no column for it. It is not a redaction filter applied on read.

- Option A (recommended, CONTEXT-locked): as described, and enforced by a schema-level test that
  enumerates the persistence layer's text-bearing fields and asserts none of them is a free-text
  reasoning field. The test is the guarantee; a future migration that adds such a column fails it.
- Option B: store reasoning and redact it on read.
Cost of undoing later: a schema that can hold chain of thought will eventually hold it, and MCP-04
forbids exposing it. Once written, it is in backups, in the change feed, and in every restore.

A note on what this does and does not cost: the arguments actually executed are still recorded in
full, so the history remains inspectable. What is absent is the model's account of why.
  </decision>
  <context>
`05-VALIDATION.md`'s MCP-04 row states the mechanism precisely: assert at the schema level that no
free-text reasoning field exists on the activity struct or table, rather than testing a read-time
filter. `05-RESEARCH.md` § Security Domain lists this as the Information Disclosure mitigation for
the phase.
  </context>
