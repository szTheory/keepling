<objective>
Give the user the two surfaces D-23 names, in the app that already exists: an agent-grant
management view, and an activity history where an agent action is visibly an agent action and is
undoable. No new client applications.

Purpose: MCP-04's requirement is user-visible history with a working recovery path. A history the
user cannot reach, and a grant the user cannot revoke, do not satisfy it.

Output: `AgentGrantList`, an agent-aware `ActivityList`, and an end-to-end Playwright spec against
the real stack that proves an agent acts, the user sees it, undoes it, and revokes the agent.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → device-grant list and revoke endpoints | Ambient cookie authentication, so CSRF protection applies |
| Server activity payload → rendered history | Task content authored by anyone reaches the DOM here |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-46 | Elevation of Privilege | revoke action | high | mitigate | Revocation goes through the existing `DELETE /api/v1/device-grants/:installation_id` endpoint on the authenticated, origin-checked pipeline; no new revocation path is introduced |
| T-05-47 | Information Disclosure | scope rendering | medium | mitigate | Displayed scopes come from the grant the server returned; a hardcoded frontend list is asserted absent, so the view cannot claim a grant holds less than it does |
| T-05-48 | Tampering | agent content in the history DOM | high | mitigate | React escapes rendered text by default and the repository's existing `security-content.test.tsx` covers this class; the new spec renders agent-authored titles through the same path |
| T-05-49 | Repudiation | agent action indistinguishable from the user's | high | mitigate | The actor is rendered for every fact with a text label and an icon, not colour alone, and is announced to assistive technology |
| T-05-50 | Spoofing | revoked grant still acting | high | mitigate | The end-to-end spec asserts a post-revocation `tools/call` is refused and creates no row, read back from the server |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install occurs in this plan; the view reuses existing UI primitives. Any future install proposal requires the package-legitimacy gate and a blocking human checkpoint first |
</threat_model>
