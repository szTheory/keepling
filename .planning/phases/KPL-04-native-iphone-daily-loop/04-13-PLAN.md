<objective>
Make accessibility release evidence rather than a checklist: an audit on every supported screen, a Dynamic Type matrix that includes the accessibility sizes, Reduce Motion and Differentiate Without Color as environment overrides, and focus safety asserted after the two moments it is most likely to break.

Purpose: IOS-03 is a requirement the project has already decided cannot be met by manual walkthroughs — there is no human UAT here. Everything provable is proven by `performAccessibilityAudit` and environment overrides, and the one thing that is not provable is disclosed by name.

Output: a closed screen inventory driving four suites, one motion gate, and the honest statement of what these suites do and do not capture.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Task content -> accessible names and screen titles | Accessible names are surfaced by assistive technology and can leak content beyond its own row. |
| System accessibility settings -> app rendering | An environment the app does not control and must remain correct under. |
| Screen inventory -> coverage claim | A screen absent from the inventory is a screen with no accessibility evidence. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
