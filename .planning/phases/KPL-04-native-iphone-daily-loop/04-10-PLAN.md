<objective>
Make the iPhone tell the truth about synchronization: one authoritative projection, one calm accessory that says nothing when there is nothing to say, one deliberate inspection sheet, and one announcement per meaningful change.

Purpose: IOS-04 is the trust requirement. The failure mode it guards against is not an ugly screen but a calm one that conceals a conflict, an expired session, or an unrecoverable store. Every surface here derives from one summary so no two surfaces can disagree.

Output: the presentation projection with its inherited copy vocabulary, the conditional bottom accessory, the full-screen Sync & Recovery sheet, inline per-task exceptions, and the debounced announcement path.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Application state -> presentation projection -> every surface | A surface that derives its own truth can contradict another surface about whether data is safe. |
| Presentation copy -> the person's trust decision | Copy that overstates completeness is the highest-severity failure this requirement guards. |
| Task content -> accessibility announcements | Announcements are spoken aloud; leaking task content into a batched summary is a disclosure surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-10-01 | Spoofing | Calm UI concealing a conflict, fence, or unrecoverable store | high | mitigate | The closed input union has one case per state and the derivation is total; an uncertain state derives its own named state and is asserted to be neither healthy nor a rejection. |
| T-04-10-02 | Spoofing | Copy claiming global synchronization completeness | high | mitigate | `Everything synced` is asserted absent from the derived copy set; the healthy sheet uses coarse last-contact copy only. |
| T-04-10-03 | Information Disclosure | Task content spoken in a batched announcement | medium | mitigate | Announcements carry bounded counts in the inherited form, not task titles; Plan 04-15's privacy scan covers the announcement text surface. |
| T-04-10-04 | Repudiation | Two surfaces disagreeing about the same state | high | mitigate | All three surfaces consume one derived summary object; no view recomputes, asserted by a source scan for priority logic in the view. |
| T-04-10-05 | Information Disclosure | Backend vocabulary exposing internal structure in user copy | low | mitigate | A test scans every derived copy string for backend vocabulary and fails on any occurrence. |
| T-04-10-06 | Denial of Service | Announcement storm on a large batch | medium | mitigate | Debouncing happens at the projection layer with one announcement per meaningful transition and a bounded batched summary. |
| T-04-10-07 | Spoofing | Reserved accessory space repurposed as a healthy status badge | high | mitigate | The recorded prohibition forbids it and the healthy-case assertion requires no text, no glyph, no count, and accessibility-hidden. |
