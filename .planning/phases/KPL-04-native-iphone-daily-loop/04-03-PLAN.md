<objective>
Write the third independent implementation of Keepling's synchronization reducer, in Swift, and prove it agrees with the existing Elixir and TypeScript implementations on every golden vector — then make that three-way agreement structurally enforced rather than incidentally true.

Purpose: D-10's N-version argument is the spine of this phase. Two agreeing implementations become corroborating evidence only when a gate refuses to let a third quietly skip a file or an action type. This plan builds both the third implementation and that gate.

Output: `SyncReducer.swift` plus a vector harness that fails on a missing case, a new `packages/contracts/vectors/manifest.json` consumer contract, and a cross-runtime gate wired into the existing contract check.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Golden vector files -> three independent runtime harnesses | The shared specification; a harness that silently skips a file degrades the corroboration all three implementations rest on. |
| Closed action vocabulary -> Swift reducer | An unrecognized action type is an unhandled state transition, which is a correctness hole rather than a no-op. |
| Reference model authority -> client reducer | The client reproduces the reference state machine; it must never become an independent source of acceptance authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03-01 | Repudiation | Vector conformance coverage | high | mitigate | Task 3's per-file executed-case set equality plus the manifest cross-consumer gate turn a silent coverage reduction into a failing test (D-15). |
| T-04-03-02 | Tampering | Vector files copied into a test bundle | high | mitigate | Vectors are resolved from the source tree by a repository-root walk; a `.copy` resource declaration is a named acceptance-criteria violation. |
| T-04-03-03 | Elevation of Privilege | Client-side acceptance authority | high | mitigate | The reducer is pure, imports no transport, and reproduces the reference model's outcomes; the recorded prohibition forbids locally deciding acceptance, revision, or conflict outcomes. |
| T-04-03-04 | Tampering | Vocabulary v1 mutation invalidating retained evidence | high | mitigate | Task 1's blocking decision checkpoint fixes a versioned superset before Swift is written, per D-16's one-way rating. |
| T-04-03-05 | Denial of Service | Unbounded pull or push batches | medium | mitigate | Contract bounds 50 and 25 are carried across as named constants and asserted by test. |
| T-04-03-06 | Information Disclosure | Vector fixture content | low | accept | Vector files are storage-neutral synthetic fixtures already committed and reviewed in Phase 2; no new disclosure surface. |
</threat_model>
