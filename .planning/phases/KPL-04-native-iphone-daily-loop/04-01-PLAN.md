  <behavior>
    - Capturing a nonempty title commits exactly one transaction that writes the visible projection row, the immutable command bytes and fingerprint, the mutation journal entry, and the outbox row, then reports local acceptance.
    - Local acceptance is reported only after the transaction commits; a store error before COMMIT leaves zero rows in every one of those four tables.

    - Pushing the queued row to a real server and applying the returned acknowledgement (matching mutation identity and fingerprint) deletes that exact outbox row and writes the terminal outcome to the journal.
    - Replaying the identical acknowledgement a second time is a no-op success, not an error.
    - A thrown URLSession error is classified as unreachable and leaves the outbox row pushable; an answered non-2xx response is classified as a decided refusal.

| Boundary | Description |
|----------|-------------|
