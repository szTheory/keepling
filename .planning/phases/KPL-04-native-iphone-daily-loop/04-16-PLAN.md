<objective>
Put Keepling on Jon's actual phone, under a profile that will not expire out from under him, and prove the trust claims on real hardware against a real server — with evidence bound to the exact bytes running on the device.

Purpose: the simulator cannot model real flash storage contention, real network transitions, real provisioning, or a real no-notice process kill. D-20 makes this lane the phase-acceptance gate for exactly those reasons, and D-21 makes attestation rather than byte reproducibility the honest way to bind its evidence.

Output: a signed build with an injected digest, a device-identifier resolver that respects the two identifier spaces, a recording-proxy real-stack lane, and the device suites for the core loop, recovery, accessibility confirmation, and the locked-device data-protection assertion.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build Mac -> signed artifact -> physical device | Code signing and provisioning are the trust chain that lets the app run at all. |
| Physical device -> recording proxy -> real Phoenix and PostgreSQL | Real bytes cross a real network to real canonical storage. |
| Recorded evidence -> phase acceptance claim | Evidence reused across builds is a false claim about the shipped artifact. |
| Locked device -> background store write | The at-rest protection class is only observable here. |
