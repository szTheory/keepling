# Phase KPL-04 — UI Design Contract

> Visual and interaction contract for Keepling for iPhone. Generated by `gsd-ui-researcher`; the checker upgrades this draft after all seven dimensions pass.

---

## Design Intent

Keepling for iPhone is the same quiet, trustworthy personal workspace as Keepling for Mac, re-expressed as a native touch application rather than a desktop window shrunk to fit a phone. Native iPhone fit outranks pixel parity with Mac or Web. Component *meaning*, task semantics, recovery language, semantic tokens, and focus safety do not drift across clients — only density, navigation shape, and gesture vocabulary are platform-specific (D-45).

The phone has no menu bar, no hover state, and no persistent chrome budget, so status must be able to disappear entirely when healthy and reappear in one fixed, learnable place — `tabViewBottomAccessory` — the moment it is actionable (D-29, D-38). A visually calm screen must never conceal data that is not durable, a conflict, an authentication fence, or an unrecoverable local-store problem. Routine local saves and healthy synchronization stay silent; actionable exceptions render inline beside the affected task and in one bounded `Sync & Recovery` sheet.

Brand is concentrated in the app icon, the selection marker, the accent, empty-state tone, and a few meaningful moments — never in repainted native chrome, tab bar, navigation bar, or system controls (D-47). The Phase 1 palette remains an approved product-token baseline, not a final brand or icon decision; Phase 4 does not specify a new logo, wordmark, mascot, or palette.

Sources: `04-CONTEXT.md` D-01–D-49 (D-25–D-49 govern this contract directly); `03-CONTEXT.md` D-01–D-48 (direct antecedent for trust language, undo, and sync presentation); `REQUIREMENTS.md` IOS-01–04; approved `01-UI-SPEC.md` and `03-UI-SPEC.md`; `docs/brand/BRAND-SEED.md`; `packages/design-tokens/tokens.json`.

## Design System

| Property | Value | Source |
|----------|-------|--------|

| Component library | Native SwiftUI (`TabView`, `NavigationStack`, `List`, `.swipeActions`, `.contextMenu`, `.sheet`, `tabViewBottomAccessory`) plus `UIAccessibility`/`XCTest` audit APIs; no third-party UI package | D-25, D-26, D-29, D-38, D-48 |
| Icon library | SF Symbols (system-provided, versioned with the SDK); never a bespoke icon font or bitmap icon set for in-app controls | Platform convention; matches Lucide's role on Mac/Web — paired with visible text or an accessible name, never color-only |
| Font | System font (SF Pro via Dynamic Type text styles); no custom face bundled | `docs/brand/BRAND-SEED.md` — "Use platform system typography… Do not force one custom face across native controls" |
| Styling | SwiftUI native modifiers backed by a **generated Swift token emitter** from `packages/design-tokens/tokens.json` (D-46); platform aliases may refine density/layout, never state meaning | D-45, D-46 |
| Theme | Follow system light/dark and react while running; preserve Increase Contrast, Differentiate Without Color, Reduce Transparency, and Reduce Motion alternatives | D-47, D-48 |

Component styling is structural and native-restrained: hairline separators, system list styling, system shadows only where the platform default already applies (sheets, menus), and no gradients, glass, floating card grids, decorative productivity imagery, perpetual spinners, or celebration effects. The renderer consumes shared presentation only through a narrow client-facing boundary equivalent to the Mac `ClientFacade`: no SwiftUI view receives raw `GRDB` records, file paths, credentials, cursors, fingerprints, or unrestricted platform APIs (D-45 inheriting Phase 3's presentation-only boundary discipline).

## Spacing Scale

Declared values are the canonical DTCG tokens (`packages/design-tokens/tokens.json`), emitted to Swift per D-46, and remain multiples of four:

| Token | Value | Usage |
|-------|-------|-------|
| `space.xs` | 4px | Icon/text gaps, compact label internal gaps |
| `space.sm` | 8px | Compact metadata rows, field help text |
| `space.md` | 16px | Default control spacing, list row internal padding |
| `space.lg` | 24px | Section padding, detail-screen groups |
| `space.xl` | 32px | Major content groups, empty-state stacks |
| `space.2xl` | 48px | Empty-state and major section separation |
| `space.3xl` | 64px | `Sync & Recovery` sheet breathing room |

iPhone density aliases, exceptions to a flat 4px grid where touch and platform conventions require it:

- Every tappable control, including icon-only swipe/context-menu actions and the bottom-accessory control, has a minimum **44×44pt** hit target (`layout.target` token; inherited Phase 1/3 value; D-48's accessibility audit asserts `.hitRegion` against this).
- Task rows are at least **52px** high (`layout.taskRowMin`), matching the Mac/Web row minimum so the same visual rhythm carries across clients.
- The `tabViewBottomAccessory` strip and the tab bar itself follow system-defined heights; do not override them with custom spacing tokens.
- One-pixel hairline separators and the 2pt-equivalent focus/selection ring are strokes, not spacing-token exceptions.

Exceptions: none beyond the touch-target and row-height aliases above.

## Typography

Use exactly four Dynamic Type-mapped roles and two weights, inherited unchanged from the Phase 1/3 token intent and re-expressed through iOS text styles so Dynamic Type scaling (not a fixed px value) is the actual runtime contract:

| Role | Base size (@ default Dynamic Type) | Weight | Nearest system text style | Usage |
|------|--------------------------------------|--------|----------------------------|-------|
| Label | 14px | Semibold (600) | `.footnote` / `.caption` (semibold override) | Row metadata, compact state labels, accessory-strip text |
| Body | 16px | Regular (400) | `.body` | Task titles, list rows, form values, recovery copy |
| Heading | 20px | Semibold (600) | `.title3` (semibold) | Screen/section headings, `Sync & Recovery` sheet title |
| Display | 28px | Semibold (600) | `.largeTitle` (semibold, where used) | Tab-root large title only, if used — do not introduce a fifth size to fill space |

All four roles must scale with the user's chosen Dynamic Type category, including the accessibility sizes, and must be verified by the D-48 snapshot matrix across content-size categories — this is release evidence, not an assumption. Long labels never force a smaller fixed size to fit; they wrap or truncate per the surface contract, with an accessible full value always reachable (mirrors the Mac `Show Full Value` disclosure pattern for long notes).

Task titles, notes, project/tag names, and drafts render as untrusted plain text in the Body role — never as attributed/rich text and never interpreted as markup.

## Navigation, Tab, and Gesture Contract

- Root is a two-tab `TabView`: **Today**, **Inbox**, each with its own `NavigationStack` (D-25). List → detail is a push, not a sheet. Capture is the only sheet-presented flow.
- Trailing swipe on a task row carries **Complete/Reopen only**, with `allowsFullSwipe: true` — the reversible action gets the cheap gesture (D-26).
- **Trash never gets a swipe action of any kind.** It is reachable only through the row's long-press `.contextMenu` and the task detail view (D-26). This is a locked anti-pattern boundary (D-49): gesture-only destructive actions and full-swipe-to-delete are both explicitly rejected.
- **No pull-to-refresh** anywhere in the app — it would imply the user can command synchronization correctness, contradicting the authoritative-projection model (D-28, D-15/D-16 inherited). **No drag-to-reorder** — ordering is not in this phase's locked capability set (D-28).
- Every gesture (swipe-complete, swipe-reopen, long-press-trash, long-press-context-actions) is **mirrored as a named, reachable control** in the task detail view and exposed via `.accessibilityActions`, so Switch Control, Voice Control, and Full Keyboard Access reach every command with no gesture-only path (D-27, D-49).
- Bottom-trailing thumb zone is shared between the conditional `tabViewBottomAccessory` (status/undo) and any capture affordance; when both could occupy the same visual slot, the accessory's priority order (below) decides which renders, and layout must not let one visually clip the other (Claude's Discretion, resolved here: capture remains reachable via the nav-bar toolbar action at all times, independent of accessory state, so the accessory never blocks access to capture).

## Capture Contract

- In-app capture is a `.sheet` with `.presentationDetents`, title-first, opened from a toolbar action reachable on both tabs (D-35).
- The sheet holds a **durable draft** exactly like Mac Quick Entry: backgrounding, dismissing, or interruption never silently discards nonempty text. Only an explicit `Discard Draft` action removes it, confirmed when nonempty (D-35, mirroring 03-CONTEXT D-11/03-UI-SPEC Quick Entry contract).
- `.keyboardShortcut` support covers hardware-keyboard commit and dismiss for the (less common but supported) hardware-keyboard-attached case (D-35).
- **App Intents for Capture and Complete** are declared in the main app target, unit-tested via direct `perform()` calls, and must not open a second store handle or strand a durable draft when the app foregrounds mid-intent (D-35, D-37).
- **Deferred, not built:** Share Extension, WidgetKit widget, Control Center/Lock Screen controls, Spotlight-index surfaces, capture while fully terminated (D-36). Do not stub UI affordances that imply these exist.

## Undo Contract

- Semantic undo is a **named, persistent `Undo {Action}` control** in the conditional `tabViewBottomAccessory`, mirrored as a named row in the nav-bar overflow menu on both tabs (D-30).
- It persists **until superseded by the next undoable semantic action or explicitly dismissed — no timer, no auto-expiry.** Timer-based (toast/snackbar) undo is a locked anti-pattern (D-33, D-49): it is unreachable in time for VoiceOver/Switch Control users and unprovable without flake in XCUITest.
- `applicationSupportsShakeToEdit = false` — shake-to-undo is explicitly disabled; it is undiscoverable, user-disableable, and untestable, so it can never carry a locked semantic command (D-31).
- `UndoManager` is used **only** for in-field text editing inside capture/detail — platform text undo and semantic undo never collide or share one control (D-32).
- Undo of an action already accepted by the server expresses as a **compensating semantic action** reconciled through the server-issued handle, exactly as the Mac client does — never a local retraction of already-accepted server state (D-34).
- Undo-versus-actionable-sync-exception arbitration in the shared accessory slot, and the exact "until superseded" scope (per-list vs. global), are Claude's Discretion at plan/execute time, within these locked meanings.

## Synchronization and Recovery Presentation

### Hierarchy (D-38, mirroring Mac's hierarchical hybrid — D-15 inherited)

1. Healthy synchronization is silent — the `tabViewBottomAccessory` is **absent**, not merely quiet.
2. After the grace period, actionable exceptions take strict priority over an undoable action, which takes priority over transient work-in-progress, in the shared accessory slot.
3. Per-task exceptions (conflict, rejection, pending) render inline beside the affected task row/detail only — never as a separate global list duplicating per-task state.
4. Deliberate inspection is the full-screen `Sync & Recovery` sheet, reachable from the accessory, from a persistent overflow-menu row on **both** tabs (so the path exists even when everything is quiet), and by deep link from any per-task exception (D-39).
5. A reject persistent status glyph in the navigation bar — that pattern is explicitly rejected (D-40); it is ambient noise and it consumes navigation-bar space needed at accessibility Dynamic Type sizes.

Every renderer-visible synchronization summary derives from one authoritative presentation projection; the UI infers no synchronization truth of its own from connectivity, timers, or absence of an error (D-41).

### Exact state language

Carries over **unchanged** from `03-UI-SPEC.md`'s "Exact state language" table (D-43), with exactly one device-specific substitution: `Saved on this Mac` → **`Saved on this iPhone`** everywhere it appears, including the compound `Sync when you're back online` and `Your changes stay on this Mac` → `Your changes stay on this iPhone` variants. The Mac's `Sync & Recovery` popover/drawer becomes the iPhone's full-screen `Sync & Recovery` sheet — same title, same copy vocabulary, different presentation container.

Never say `Everything synced` from one successful lane. The healthy `Sync & Recovery` sheet may say `No changes need your attention` and show coarse copy such as `Last successful contact: 8 minutes ago`, never claiming global completeness. Never use backend words — outbox, cursor, SQLite row, fingerprint, bootstrap, transport retry — in primary copy.

### Conflict resolver

Same meaning as Mac's inline resolver (03-UI-SPEC "Conflict resolver"), re-expressed as a native detail-view section: affected fields only, labeled `Your Version` / `Current Version`, `Use Mine` / `Use Current`, `Keep Editing` returns without mutation, nonconflicting draft fields preserved, resolution uses a fresh semantic command against current server truth. Long notes use an accessible `Show Full Value` disclosure rather than shrinking type.

### Announcements

Emit **one debounced `AccessibilityNotification.Announcement` per meaningful transition**, debounced at the projection layer (not per view), with `.high` priority reserved for actionable exceptions (D-42). Never announce every sync acknowledgement individually; batch into a bounded summary as Mac does (`3 changes saved on this iPhone`).

### Notifications

**Zero OS notifications in this phase** — none for routine save, ready, retry, reconnect, prolonged outage, or synchronization, and no reminders or scheduled local notifications of any kind (D-44). Status stays entirely in-product.

## Copywriting Contract

Inherits Phase 3's voice, vocabulary, and sentence-case convention verbatim (D-43, D-45), with the `Saved on this Mac` → `Saved on this iPhone` substitution applied everywhere. Use sentence case in in-app controls; iOS system UI (tab labels, nav titles, alert titles) follows platform title-casing conventions where the OS itself renders the chrome.

| Capture prompt | `What do you want to keep?` |
| Capture destination | `Destination: Inbox` |
| Optional placement | `Add to Today` |
| Capture commit | `Add Task` |
| Editor primary | `Save Changes` |
| Inbox clarification | `Save & Move Out of Inbox` |
| Editor secondary | `Cancel Editing` |
| Reauthentication | `Sign In and Continue` |

### Empty states

| View | Heading | Body / next step |
|------|---------|-------------------|
| Inbox | `Inbox Is Clear` | `Captured tasks appear here until you move them out.` — `New Task` |
| Today | `Nothing for Today` | `Add a task or choose an existing task to make it part of today.` |
| No changes need attention (`Sync & Recovery`) | `No Changes Need Your Attention` | Show coarse last successful contact; never claim everything is synced |

Trash is reachable only through detail/context menu in this phase, not a standalone empty tab; its "no trashed tasks" state uses the same voice if a dedicated screen is built: heading `Trash Is Empty`, body `Tasks moved to Trash stay recoverable here.`

Opening, preparing, updating, and failed-loading states never reuse empty-state copy (inherited Mac rule).

### Error and state copy

Inherit the full `03-UI-SPEC.md` "Exact state language" table verbatim with the `this Mac` → `this iPhone` substitution (see Synchronization section above); do not restate it here to avoid copy drift between the two documents.

### Destructive and consequential actions

| Action | Confirmation approach and exact copy |
|--------|----------------------------------------|
| Complete a task (swipe/full-swipe) | No confirmation — reversible via the persistent Undo control |
| Move one task to Trash (context menu / detail only, never swipe) | No preconfirmation because it is recoverable; after local commit show `Task moved to Trash. Undo Trash` in the bottom accessory |
| Discard capture draft | Heading `Discard Quick Entry Draft?`; body `This draft is saved on this iPhone but hasn't been added as a task.` Actions: destructive `Discard Draft`, safe `Keep Draft`; default focus `Keep Draft` |
| Discard editor changes | Heading `Discard Unsaved Changes?`; body `These edits haven't been saved.` Actions: `Save Changes`, destructive `Discard Changes`, safe `Keep Editing`; default focus `Keep Editing` |
| Sign out | Fence the namespace and preserve its local intent; if capture/editor is dirty, resolve the draft with the corresponding safe dirty-work dialog first |

There is no server hard-delete, local cryptographic-erasure claim, bulk task deletion, or routine OS notification in Phase 4 (D-44).

## Accessibility and Platform Contract

- Meet WCAG 2.2 AA and pass `performAccessibilityAudit(for: [.contrast, .dynamicType, .textClipped, .hitRegion, .elementDetection, .sufficientElementDescription, .trait])` on every supported screen: Today, Inbox, capture sheet, task detail/editor, conflict resolver, `Sync & Recovery` sheet, and every dirty-work/discard confirmation (D-48).
- Test across the accessibility Dynamic Type range, `accessibilityReduceMotion`, and `accessibilityDifferentiateWithoutColor` environment overrides, plus one physical-device confirmation run (D-22 Criterion 4, D-48).
- Every icon-only action (swipe action, context-menu item, accessory control, toolbar button) has an action-and-object accessible name such as `Complete "Call dentist"`, `Trash "Call dentist"`, `Undo Trash`, `Open Sync & Recovery`. Screen titles never leak quoted task content into system chrome the way window titles do not on Mac.
- Every gesture-bound command is independently reachable via `.accessibilityActions` and a mirrored visible control (D-27) — no gesture-only path exists anywhere in the app.
- Safe focus after row removal and sheet dismissal is asserted, not assumed: focus moves to the next row, then previous row, then the screen heading, mirroring the Mac contract.
- Completion, pending, conflict, selected tab, selection, warning, error, authentication, and destructive intent remain understandable without color, sound, or motion (D-48's Differentiate Without Color pass enforces this).

## Motion

Use roughly 140–180ms ease-out for direct interaction acknowledgement (row selection, swipe settle, accessory appearance/disappearance), matching the Mac/brand-seed range. Capture gently settles into place; completion closes with precise restraint, no confetti; undo visibly restores continuity; conflicts pause and separate rather than shaking or alarming (brand seed motion character).

Under Reduce Motion, state changes are immediate or use opacity only, no longer than ~100ms. Disable row-translation animation, decorative transitions, and any drag-following animation. No durability, selection, conflict, undo, or error meaning may depend only on animation — every one of those states already carries text and/or an SF Symbol per the Color and Copywriting contracts above.

## Verification Evidence Required

- XCUITest (simulator, required gate) covers populated, authoritative empty, opening, preparing, updating, offline, local-save failure, retryable server failure, uncertain acceptance, rejection, conflict, authentication fence, and unrecoverable local-store states with exact copy from the inherited state table.
- XCUITest covers complete Full Keyboard Access/Switch Control operation, swipe-vs-full-swipe boundaries (Complete only), Trash reachable only via context menu/detail, capture draft retention across backgrounding/interruption, App Intent `perform()` unit tests, focus safety after row removal and sheet dismissal, and undo persistence "until superseded."
- `performAccessibilityAudit` plus snapshot tests across accessibility Dynamic Type sizes, `accessibilityReduceMotion`, and `accessibilityDifferentiateWithoutColor` environment overrides on every supported screen (D-48), plus one physical-device confirmation run (D-20, D-22 Criterion 4).
- Physical-device lane (`xcodebuild test -destination 'platform=iOS,id=UDID'` + `devicectl`) gates phase acceptance and proves: core loop on the installed signed build; offline/termination/relaunch/expired-auth/fencing/duplicate-replay/conflict driven server-side through the recording proxy; background-is-only-acceleration via injected task-handler invocation; and the D-9 backup-exclusion/replay-no-op adversarial fixture. Evidence is bound by D-21 provenance-plus-read-back attestation (`KeeplingBuildDigest` Info.plist key, read back from the running process), never by byte reproducibility.
- Privacy tests prove task text, drafts, commands, credentials, tokens, cursors, fingerprints, and raw identifiers never enter on-device diagnostics, App Intent metadata, Spotlight/Shortcuts surfaces, or unrestricted platform APIs (D-23).
- Criterion 5 ("daily use without opening Things") is explicitly **not automatable**; the closest automatable proxy is a non-expiring-profile install passing every device-lane case, with sustained adoption left to owner dogfood feedback per D-22 and the project's no-human-UAT posture applied to everything that *can* be automated.
