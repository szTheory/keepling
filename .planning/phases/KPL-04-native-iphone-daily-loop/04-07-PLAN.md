<objective>
Give the iPhone a real identity on Jon's server: the existing device-grant flow, credentials in the Keychain, a namespace that comes only from the server, and an authentication fence that is its own honest state rather than a mutation failure in disguise.

Purpose: every later plan's correctness assumes account isolation. A store that activates on a client-guessed namespace, or a 401 that looks like a rejection, breaks that assumption quietly. This plan makes both structurally impossible before the orchestrator starts running sync passes.

Output: a PKCE device-grant client, a Keychain credential store behind a replaceable port, server-only namespace activation, and fencing proven across an account switch.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| System browser -> app callback -> token endpoint | The authorization code crosses process boundaries; a callback scheme collision is an interception surface. |
| Server token response -> local namespace activation | The only legitimate source of account authority on the client. |
| Keychain -> app process | The only place credentials live; every other on-device surface is a leak. |
| Account A local intent -> Account B session | Two accounts sharing one phone must not share one byte of intent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-07-01 | Spoofing | Authorization callback interception | high | mitigate | `ASWebAuthenticationSession` with a registered callback scheme plus PKCE, so an intercepted code is unusable without the verifier (ASVS V2). |
| T-04-07-02 | Elevation of Privilege | Client-derived namespace activating local storage | high | mitigate | Activation's only namespace input is the decoded authenticated token response; no overload accepts an assembled namespace (ASVS V4). |
| T-04-07-03 | Information Disclosure | Credentials in UserDefaults, plists, the store, or logs | high | mitigate | Keychain-only storage at `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` with synchronizable false, plus a leak-scan test asserting the actual secret values appear nowhere else (ASVS V6/V8). |
| T-04-07-04 | Elevation of Privilege | Account B reading or pushing Account A's local intent | high | mitigate | Account-switch fencing test proves refusal on read, push, and settle across namespaces. |
| T-04-07-05 | Repudiation | 401 collapsed into a mutation rejection | high | mitigate | Authentication-required is a distinct tagged state produced by the Plan 04-05 classifier and never an acknowledgement outcome. |
| T-04-07-06 | Elevation of Privilege | Usable credentials surviving a failed sign-out | high | mitigate | Sign-out writes the fence and clears the Keychain before attempting revocation; asserted with a throwing revocation. |
| T-04-07-07 | Tampering | Refresh handle replay | high | mitigate | The client never reuses a rotated handle and treats a server replay answer as terminal; the server-side family fence advance is Phase 2 behavior relied on, not reimplemented (ASVS V3). |
| T-04-07-08 | Denial of Service | Local data removal triggering a server deletion | high | mitigate | The removal path takes no transport port, making server deletion structurally unreachable rather than merely uncalled. |
</threat_model>
