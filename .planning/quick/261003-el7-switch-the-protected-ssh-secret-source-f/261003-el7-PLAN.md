# Switch the protected SSH secret to a local key file

## Objective

Let Jon provision only `KEEPLING_SSH_PRIVATE_KEY` from a local path configured in the ignored root `.env.local`, without a 1Password session. Keep the actual key outside the checkout and stream its bytes directly to the configured GitHub protected Environment secret.

## Decisions

- `.env.local` contains one unquoted absolute path assignment named `KEEPLING_SSH_PRIVATE_KEY_FILE`; it never contains key bytes.
- The key must be a dedicated, user-owned, mode-0600-or-more-restrictive, unencrypted ED25519 private key stored outside the repository. The current hosted workflow cannot unlock a passphrase-protected key noninteractively.
- Add narrow check and apply modes so SSH-key setup has no `op` CLI dependency. The apply mode must recheck the existing reviewer, main-only deployment policy, and stable `main` protections; it must not create or weaken the Environment.
- Bulk provisioning of the other mapped secrets remains unchanged and still uses 1Password.
- Do not read or modify `.env.local`, generate a key, or upload any value in this task; the owner has not supplied a key-file path.

## Tasks

1. Replace the `env-local:` 1Password-reference source with `env-local-file:` for the protected SSH secret. Validate root `.env.local` as ignored, inert data; require one exact assignment, an external regular readable current-user file without group/other access, and an unencrypted ED25519 identity. Stream the key directly to `gh secret set` without printing the path or value.
2. Add `--check-ssh-key` and `--apply-ssh-key` to the existing provisioning helper. These modes must not invoke 1Password. Upload only after the existing read-only GitHub preflight confirms reviewer, main-only deployment policy, and stable `main` protection.
3. Document key creation and local path setup. Add hermetic regression coverage for local validation, no-1Password behavior, exact stdin upload, and refusal when Environment protection is missing; run it in the existing repository-integrity CI lane. Run shell syntax and whitespace checks, commit only this task's source/docs/GSD artifacts, push to PR #14, and use GitHub CI as the integration gate. Investigate the prior iOS simulator accessibility failure if it recurs.

- Inspect the diff to confirm no key bytes or local path are committed or printed.

## Completion criteria
